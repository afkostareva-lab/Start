# Spotlight: страницы для изучения модуля

Этот скилл повторяет то, что сделано для Module 3 (файлы `module3.html`, `module3-words.html`,
`writings.html` в корне репозитория). Пользователь — школьница или её родитель: пишет по-русски,
смотрит всё с iPhone, присылает скриншоты страниц учебника и Pinterest-референсы. Объясняй
по-русски, простыми словами, без жаргона; английский — только в учебном материале.

## Что получается на выходе

| Файл | Что внутри |
|---|---|
| `moduleN.html` | Постер-обложка, меню всех частей, по каждой части: постер, теория по-русски, пересказ текста по-русски, **полный английский текст** с кликабельными жирными словами и таблицей к ним, упражнения из учебника с проверкой, Progress Check на 100 баллов, чек-лист «Now I can…» |
| `moduleN-words.html` | Все слова Word List этого модуля по частям + слова из текстов. Режимы: список, карточки, тест, написание |
| `moduleN-writings.html` | Образцы для всех письменных заданий модуля (`<title>Writings</title>`) |
| `mN-icon.png`, `mN.webmanifest` | Иконка и манифест для экрана «Домой» |
| `spotlight-sw.js` | Общий для всех модулей офлайн-кэш (см. «Офлайн») |

Для модуля 3 страница образцов называется просто `writings.html` — её не переименовывай,
у неё уже есть ссылка у пользователя.

## Порядок работы

### 1. Собери материал
Нужны скриншоты: обложка модуля (список тем), каждая часть a/b/c/d, Culture Corner, English in
Use, Extensive Reading / Across the Curriculum, Progress Check, и **страницы Word List этого модуля**.
Если чего-то не хватает — попроси одним сообщением, перечислив, каких страниц нет. Если вложение не
пришло («вот скрин», а картинки нет) — так и скажи, не выдумывай содержимое.

Внимательно перепиши тексты со скринов: они нужны дословно (полный английский текст) — жирные слова
отметь сразу. Ответы к упражнениям реши сам и перепроверь по тексту: ключа в учебнике нет.

### 2. Страница модуля — из шаблона
Скопируй `assets/reference/module3.html` → `moduleN.html` и замени содержимое, **не трогая CSS и
движок**. Карта шаблона — в `references/structure.md` (прочитай перед правкой). Коротко:
- `<header class="hero">` — гигантская цифра модуля, строчный жирный заголовок с точкой
  («profiles.»), рукописная подпись (*learn anything!*), лид по-русски.
- `<nav class="toc">` — сетка 4×2: части модуля + Use + History + Check + «↑ Наверх».
  Подписи короткие (≤ 14 символов), иначе обрежутся на iPhone SE. Больше 8 кнопок — сетка
  `repeat(4,1fr)` даст 3 ряда, это нормально.
- Каждая `<section class="unit">` начинается с `.poster` — тона чередуй: cream → dark → red →
  cream → dark → soil → cream. Заголовок строчными с точкой, одно слово в `<em>` (курсив Bodoni),
  для Progress Check — `<span class="circled">`.
- Тексты: русский пересказ (`.card.text`) + полный английский оригинал в
  `<div class="card text orig" id="txt-KEY">`, жирные слова учебника обернуть в `[[…]]`, рядом
  `<tbody id="tbl-KEY">`, а в JS — запись `BOLD.KEY` с `[форма для таблицы, перевод, пример из текста]`.
  Ключ в `BOLD.KEY` должен совпадать с текстом внутри `[[…]]` буква в букву.
- Упражнения — `<div class="ex" data-ex="ID">` + данные в `EX.ID`:
  `{q:"текст с ___", o:[варианты], a:индекс, w:"пояснение по-русски"}` или
  `{t:"order", pre:"Mr Brown is", words:[...правильный порядок]}`.
- Progress Check: у каждого блока `data-pts` = баллы за вопрос, сумма максимумов = 100.
- Старые данные модуля 3 (`HOBBIES`, `CHAR`, `APP`, `PRON`, `DLG`, `U3`) замени своими или удали
  вместе с разметкой, которая их использует (`#hobbies`, `#charTbl`, `#appTbl`, `#pron`, `#dlg`).

### 3. Страница слов
Скопируй `assets/reference/module3-words.html` → `moduleN-words.html`, поменяй заголовки, ключ
`KEY="mNwords"` (иначе отметки «знаю» смешаются с модулем 3) и строки `RAW`:
`Раздел|english|перевод|пример`. Разделы начинай с номера части (`4a News`, `4b …`) — так работает
фильтр и проверка.

Правила, которые пользователь задал явно:
- **Все** слова Word List этого модуля должны быть, по своим частям. Переводы — из Word List.
- Слова **других** модулей, попавшие на тот же скрин, не добавляй.
- Слова из текстов модуля, которых нет в Word List, можно оставить — их не удаляй, а перечисли.
- Пример — по возможности фраза из текстов модуля.
- Форму бери как в Word List (blood samples, а не blood sample). Общие слова вроде grey/red/long
  в части про внешность пиши как grey hair, red hair.

Проверь: `python3 scripts/check_wordlist.py moduleN-words.html wordlist.json`
(формат `wordlist.json` — в начале скрипта). Добивайся «не хватает 0» по всем частям.

### 4. Письменные образцы — отдельный файл
Возьми `assets/reference/writings.html` как шаблон. По одному образцу на каждое письменное задание
модуля (обычно в Writing-блоках частей и Portfolio). Требования:
- Укладывайся в объём задания (страница сама показывает число слов рядом с заголовком; 90 слов
  → 85–95, «80–100» → внутри диапазона). Модуль 3 сначала получил образцы по 66 и 81 слову — это ошибка.
- Жирным — то, что ученик заменит своим. Под образцом — план по-русски.
- Где задание про Россию — бери реальные и проверяемые факты.
- **В странице модуля об образцах ни слова**: ни раздела, ни пункта меню, ни ссылки.

### 5. Без ссылок между страницами
Пользователь открывает файлы и в просмотре айфона, где переходы между файлами не работают, —
лишняя ссылка «теория →» была убрана по её просьбе. Не добавляй ссылки между страницами,
если она сама не попросит.

### 6. Офлайн и иконка
1. `python3 scripts/inline_fonts.py moduleN.html moduleN-words.html moduleN-writings.html` —
   встраивает шрифты (latin + cyrillic) прямо в файлы, ~400 КБ на страницу. Нужна сеть до
   fonts.googleapis.com; без неё — скажи и оставь `<link>` (страницы работают, только шрифты системные).
2. `node scripts/make_icon.js moduleN.html N "название." mN-icon.png`
3. `mN.webmanifest` — копия `assets/reference/m3.webmanifest` с `start_url: moduleN.html`, `mN-icon.png`.
4. **Один service worker на сайт.** Два воркера с одной областью вытесняют друг друга, поэтому
   при первом новом модуле: положи `assets/spotlight-sw.js` в корень, впиши файлы всех модулей в
   `FILES`, и во **всех** страницах (включая модуль 3) замени регистрацию `m3-sw.js` →
   `spotlight-sw.js`, а в `<head>` — `m3.webmanifest`/`m3-icon.png` на свои. При любой следующей
   правке страниц поднимай номер `CACHE` — иначе телефон покажет старую копию.

### 7. Проверка — до того, как показывать
```
node .claude/skills/spotlight-module/scripts/verify_pages.js moduleN.html moduleN-words.html moduleN-writings.html <папка_скриншотов>
```
Скрипт ловит всё, на чём модуль 3 уже спотыкался (см. «Грабли»). Добивайся «Всё в порядке», потом
**посмотри скриншоты** светлой и тёмной темы глазами: наложения гигантской цифры на текст, обрезанные
подписи, нечитаемый контраст.

### 8. Сдача
- Копии файлов — в корень и в `docs/` (GitHub Pages может брать любую из папок).
- Коммит и пуш в рабочую ветку сессии. Пришли файлы через SendUserFile (`display: "attach"`).
- Опубликовать на сайт: https://afkostareva-lab.github.io/Start/ собирается из ветки по умолчанию
  `claude/lumen-competitor-content-analysis-p96njp`. Нужен pull request в неё и merge — **спроси
  разрешения** каждый раз (до сих пор она отвечала «да»). Для merge нужен полный 40-символьный SHA.
- После merge рабочая ветка считается влитой: следующую работу начинай с ветки по умолчанию.
- Расскажи, как открыть: Safari по ссылке → «Поделиться» → «На экран „Домой“». Из приложения
  «Файлы» айфон HTML в Safari не откроет — поэтому и нужен сайт.

## Дизайн (не придумывай заново)

Всё уже в CSS шаблонов — копируй как есть. Для понимания:
- Палитра (с её Pinterest-референсов): Sceptre Red `#4D0E12`, Java Brown `#231815`, Potting Soil
  `#4A2E27`, Cerulean Blue `#A5BCD6`, Transparent Yellow `#F5EFC6`, Buttercream-фон `#EFE6DA`.
  Тёмная тема — по `prefers-color-scheme` и кнопке «◐ тема».
- Стиль — редакционные постеры: жирный строчный гротеск **Inter Tight 900** с точкой в конце,
  курсив **Bodoni Moda** для акцентных слов и английских примеров, рукописный **Pinyon Script**,
  мелкие подписи заглавными с разрядкой в углах, стрелка «→», обводка слова от руки (`.circled`).
- Упражнения — бордовые панели с кремовыми «пилюлями»; верно — голубой с ✓, ошибка — зачёркнуто.
- Bodoni Moda и Pinyon Script без кириллицы: русский текст ими не набирай (браузер подставит
  Playfair Display, но лучше русским — Inter Tight).

Если она пришлёт новые референсы — меняй токены `:root` и стили, но сохрани всё поведение.

## Грабли, на которых уже спотыкались

- **Номер вопроса внутри текста.** Движок сам ставит «1.», «2.» — в `q:` номера из учебника не пиши,
  иначе выйдет «1. 1 became…». Она это заметила и обвела на скрине.
- **Одно имя `const`/функции дважды** в одном `<script>` (было: `mark` в движке и в меню) — падает
  весь скрипт, все упражнения мертвы. Новые функции называй уникально.
- **Меню прокручивало само себя** (`scrollIntoView` в обработчике подсветки) и сбивало переход —
  «нужно отщёлкивать по одному». В шаблоне это уже исправлено: сетка вместо ленты, без scrollIntoView.
- `scroll-padding-top` должен быть больше высоты липкого меню (сейчас 120px), иначе постер прячется под ним.
- Пропуски в оригинальном тексте, которые заполняются в упражнении ниже, оставляй пустыми
  (`<span class="gap">1</span>`), чтобы не выдать ответ.
- Сложный python в heredoc внутри Bash может отклонить проверка безопасности — пиши скрипт файлом
  в scratchpad и запускай его.
- Не утверждай, что сайт открывается, если не проверил: из этой среды github.io может быть недоступен.
